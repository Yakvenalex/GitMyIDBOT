# Telegram ID Bot

Бот для получения Telegram ID пользователей, ботов, групп и каналов.

Работающий бот: [@get_tg_ids_universeBOT](https://t.me/get_tg_ids_universeBOT).

В версии 1.1.1 исправлен список пользователей в админке: имена с HTML-символами выводятся безопасно, длинный список разбивается на несколько сообщений.

## Возможности версии 1.1.0

- Выбор пользователя или бота через современные кнопки Telegram (`request_users` / `users_shared`).
- Выбор публичных и закрытых групп, а также каналов; название и username отображаются, если Telegram их передал.
- Карточки с ID, именем/названием, username и кнопкой копирования ID.
- Определение источника пересланного сообщения: пользователь, бот, группа или канал.
- `/id` в личном чате показывает ваши данные; в группе — ID чата и текущей темы.
- `/id` в ответ на сообщение участника дополнительно показывает его ID. Для сообщений анонимных администраторов выводится ID чата, от имени которого они пишут.
- `/help` со справкой, `/start` с главным меню.
- Проверка подписки на настроенные каналы перед использованием ID-функций в личном чате. Результат успешной проверки сохраняется в базе.
- Админка с просмотром пользователей и рассылкой текста, фото, документов, видео и аудио.

При скрытом авторе пересылки Telegram не передаёт его ID. Бот объясняет это ограничение и предлагает воспользоваться выбором пользователя. Произвольный поиск ID человека по `@username` не поддерживается.

Для работы в группе добавьте туда бота. Если в группе несколько ботов, используйте `/id@get_tg_ids_universeBOT`.

## Установка

Требуется Python 3.10+; на сервере используется Python 3.12.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
chmod 600 .env
```

Заполните `.env`:

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Токен бота из BotFather |
| `ADMIN_ID` | Telegram ID администратора |
| `BASE_URL` | Публичный HTTPS-адрес без пути webhook |
| `HOST` | Адрес прослушивания, по умолчанию `127.0.0.1` |
| `PORT` | Локальный порт, по умолчанию `8041` |
| `WEBHOOK_PATH` | Путь webhook, по умолчанию `/telegram/webhook` |
| `WEBHOOK_SECRET` | Случайный секрет для проверки webhook-запросов |

Для генерации секрета можно использовать `openssl rand -hex 32`. Секрет передаётся Telegram при регистрации webhook и проверяется по заголовку `X-Telegram-Bot-Api-Secret-Token`.

Список обязательных каналов задаётся в `kb_list` в `create_bot.py`. Бот должен быть администратором этих каналов. База `bot.db` создаётся в рабочей директории; `.env`, база и резервные копии исключены из Git.

## Развёртывание на сервере

Unit [deploy/get-id-bot.service](deploy/get-id-bot.service) настроен для `/home/GitMyIDBOT`. При другом расположении проекта измените пути.

```bash
sudo install -m 0644 deploy/get-id-bot.service /etc/systemd/system/get-id-bot.service
sudo systemctl daemon-reload
sudo systemctl enable --now get-id-bot.service
```

[deploy/get-id.postal-goose.ru.nginx](deploy/get-id.postal-goose.ru.nginx) — начальная HTTP-конфигурация nginx для проксирования к приложению. После подключения домена установите HTTPS-сертификат через Certbot. На рабочем сервере сертификат уже установлен и продлевается автоматически; повторно заменять действующую nginx-конфигурацию HTTP-шаблоном не нужно.

После обновления зависимостей и кода:

```bash
.venv/bin/python -m pip install -r requirements.txt
sudo systemctl restart get-id-bot.service
sudo journalctl -u get-id-bot.service -n 50 --no-pager
curl -fsS https://get-id.postal-goose.ru/health
```

Проверка `/health` возвращает `{"status":"ok","version":"1.1.1"}`. При запуске регистрируются webhook и команды, администратору отправляется уведомление. Если уведомление не удалось доставить, запуск продолжается.

## Тесты

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Тесты проверяют настоящую маршрутизацию aiogram, HTML-экранирование, копирование, приватность пересылок, подписку и совместимость с рассылками. Telegram API заменён заглушкой, для проверки базы используется временный SQLite-файл; рабочая база не изменяется.
